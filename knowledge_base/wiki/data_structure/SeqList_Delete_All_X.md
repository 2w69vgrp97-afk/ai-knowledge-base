# SeqList Delete All X

## 核心概念

顺序表删除所有值为 x 的元素，本质上是把所有不等于 x 的元素原地压缩到表的前部。

这种方法避免了每遇到一个 x 就执行一次普通删除造成的重复移动。

## 核心代码模板

```cpp
struct SeqList {
    int data[1000];
    int length = 0;
};

void deleteAllX(SeqList& list, int x) {
    int k = 0;
    for (int i = 0; i < list.length; ++i) {
        if (list.data[i] != x) {
            list.data[k] = list.data[i];
            ++k;
        }
    }
    list.length = k;
}
```

## 手写步骤

1. 设置 `k = 0`，表示下一个非 x 元素的写入位置。
2. 从前到后扫描顺序表。
3. 当前元素等于 x 时跳过。
4. 当前元素不等于 x 时写入 `data[k]`，然后 `k++`。
5. 扫描结束后令 `length = k`。

## 边界条件

空表：

扫描次数为 0，`length` 仍为 0。

全是 x：

`k` 最终为 0，必须令 `length = 0`。

没有 x：

每个元素都会被写回，`k` 最终等于原表长。

连续 x：

覆盖法不会因为元素前移而跳过检查。

如果使用逐个 Delete 的写法，删除当前位置后不能立刻无条件 `i++`。

尾部残留：

`length = k` 后，尾部旧数据不再属于有效元素。

## 常见错误

- 删除一个 x 后立刻整体前移，导致重复移动过多。
- 忘记执行 `length = k`。
- 误以为尾部残留旧数据仍是有效元素。
- 空表时没有考虑扫描次数为 0。
- 全是 x 时没有把表长更新为 0。
- 采用普通删除写法后仍然无条件 `i++`，连续 x 会被跳过。
- 覆盖法中忘记写 `length = k`，导致逻辑删除不完整。

## 典型题型

- 删除顺序表中所有值为 x 的元素。
- 要求算法保持剩余元素相对顺序。
- 分析一次扫描方法和多次删除方法的差异。
- 讨论空表、全是 x、没有 x 的边界。

## 识别信号

- 题目出现“删除所有值为 x 的元素”。
- 题目出现“删除多个元素”。
- 题目要求原地完成或空间复杂度 O(1)。
- 题目描述边遍历边删除。
- 测试样例中可能有连续 x。
- 代码中出现“删除当前位置后继续 `i++`”时，要警惕跳元素。
- 看到“保持剩余元素相对顺序”，优先想到覆盖法。

## 复杂度分析

时间复杂度：O(n)，只扫描一次顺序表。

额外空间复杂度：O(1)，只使用少量变量。

该方法保持非 x 元素的原有相对顺序。
