Prefill 和 Decode 是 Transformer 推理中的两个重要阶段。

Prefill 阶段主要处理已有输入 token。
此时模型会一次性读取大量 token，
并同时进行 Attention 和矩阵乘法计算。

由于会形成较大的矩阵运算，
GPU 可以同时调用大量计算核心进行并行处理，
因此 Prefill 阶段通常具有较高的 GPU 利用率，
整体更偏向 compute-bound。

Decode 阶段则是在已经生成部分 token 后，
继续逐个生成新的 token。

每生成一个新 token，
模型都需要：
1. 计算当前 token 的 Query
2. 读取所有历史 KV Cache
3. 与历史 Key 进行 Attention 计算

由于当前通常只有一个 Query，
Attention 更接近 1×N 的计算形式，
GPU 的大量计算核心难以被充分利用。

与此同时，
随着上下文长度增加，
历史 KV Cache 会越来越大，
系统需要不断搬运和读取大量历史数据。

因此，
Decode 阶段往往逐渐从 compute-bound
转变为 memory-bound，
系统瓶颈开始集中在：
- memory bandwidth
- cache 访问
- 数据搬运
- pipeline 调度

在 AI 推理优化中，
PagedAttention、
KV Cache 分页、
Continuous Batching 等技术，
本质上都在尝试优化 Decode 阶段的数据流与内存访问效率。

对于 FPGA 和 AI Accelerator，
Prefill 与 Decode 的差异非常重要，
因为两者对：
- 并行度
- buffer
- cache
- bandwidth
- pipeline

的需求并不相同。
